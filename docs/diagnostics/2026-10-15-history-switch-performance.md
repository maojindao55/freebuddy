# 旧会话切换性能优化

用户报告每次切到旧会话时整体卡顿 10–30 秒，随后恢复。本次优化限制切页时的工作量，并复用已处理的历史；现有诊断包没有切页时的 CPU profile，尚不能把该时长归于一个已确认的热点。

- 首屏和后续读取每页默认 20 条，单页内容预算 200 万字符。按完整消息分页，超出预算的消息留给下一页，保留原有游标顺序。
- 共享历史缓存复用 JSON 解析与消息气泡整理结果，按消息 ID 和实际内容检查版本。运行中的新内容替换旧版本，消息状态仍走现有刷新路径。缓存最多 80 个条目、原始内容总计 400 万字符；解析对象本身还会有额外内存开销。
- 历史文本片段先批量合并，再整理工具状态，减少逐片段重复处理。保留旧格式消息、错误去重和工具更新语义。
- 思考和工具详情使用原生 details 的展开状态按需构建正文，运行中的工具仍默认展开。原先过程分组已有按需渲染，本次保留该行为并补齐内部详情。

首屏减少意味着用户可能更早看到“加载更早消息”入口。折叠详情展开前没有正文 DOM，需展开后使用页面文本查找；历史数据和保存格式没有因此截断。

## 验证

- `npm run typecheck`、Electron 编译、渲染产物构建通过。
- 完整 `npm test`：1,986 通过、238 因平台/运行器条件跳过。
- 新增缓存失效、LRU/内容预算、旧格式与工具语义一致性、折叠正文不执行的回归测试。
- Electron SQLite 测试验证按条数和内容量分页，完整遍历无消息丢失或内容截断，包括相同创建时间的游标边界。
- Electron 实际组件验证：思考和结果展开/关闭、运行工具默认展开及完成关闭、跨会话切换、过程分组内按需展开。

本机 Mac 合成预处理对照：10 条消息，每条约 40 万字符、7,999 个保存项；7 次测量取中位数。旧的解析/净化/逐项整理约 21.4ms，新首次处理约 15.0ms，缓存命中后不再执行这些步骤。此测量不包括数据库、IPC、React 提交或布局，也没有复现用户 Windows 的 10–30 秒时长。

本地交互夹具：启动 Vite 后打开 `/tests/fixtures/history-performance-preview.html`。检查切换会话后正文、工具状态和展开交互；正式验收仍应使用用户的历史会话，在 Windows 上分别记录首次打开和再次切回的主进程/渲染进程长任务。文件索引读取等其他切页工作仍可能贡献耗时，不能只凭预处理微基准认定所有卡顿已解决。
