# MCP 浏览器授权

远程 MCP 服务可以使用自定义请求头，或通过浏览器完成 OAuth 授权。OAuth 适用于支持授权码和 PKCE S256 的 HTTP / SSE 服务。

## 使用

1. 打开设置中的 MCP 服务器，添加 HTTP 或 SSE 连接并填写 MCP 地址。
2. 认证方式选择“浏览器授权（OAuth）”，点击“保存并授权”。
3. 在系统浏览器登录服务账号并确认授权，然后返回 FreeBuddy。授权成功后自动运行自检。
4. 在对话中选择该 MCP 服务器。后续会话使用已有授权，并在需要时刷新令牌。

高级设置中的客户端 ID 和权限范围可以留空。默认使用服务声明的动态客户端注册；服务要求预注册公共客户端时填写客户端 ID。权限范围使用服务的认证提示，或填写由空格分隔的指定 scope。

浏览器授权最长等待 10 分钟，可在设置中取消。连接自检的超时单独计算。服务要求的账号绑定仍需在该服务自身的页面完成。

## 凭据与断开

OAuth 凭据由 Electron 主进程管理，使用操作系统安全存储加密。没有可用的系统密钥库时仅保存在内存中，退出 FreeBuddy 后需要重新授权；Linux `basic_text` 后端也采用这种方式。

桥接子进程通过限定到服务器的本地凭据接口获取短期访问令牌，不接收刷新令牌。修改地址、认证方式、客户端 ID 或权限范围会使旧授权失效。断开连接会清除本地凭据并撤销桥接访问；这不等同于撤销服务端的全部账号授权，后者应在服务自身的授权管理页面操作。

临时网络故障不会删除已有刷新令牌。服务确认授权已失效时，需要重新在浏览器授权。

## 服务要求

- MCP 端点通过 `401` 的 `WWW-Authenticate` 或标准发现地址提供 OAuth 资源和授权服务器元数据。
- 支持授权码、PKCE S256，以及公共原生客户端；可动态注册或预先分配客户端 ID。
- 允许注册 `http://127.0.0.1:<随机端口>/freebuddy/mcp/oauth/callback` 回调。
- 远程地址及认证端点使用 HTTPS。本地开发允许 loopback HTTP。

当前不包含需要用户保存客户端密钥的机密客户端模式，也不复用其他应用或浏览器中的登录凭据。
