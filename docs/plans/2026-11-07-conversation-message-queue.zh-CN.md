# 会话消息队列

状态：已接入真实发送流程。采用已选定的方案 3：输入框上方的紧凑队列入口，点击展开浮层。

## 使用范围与交互

桌面端已有的普通单 Agent 会话支持排队。Agent 正在执行时，输入框可以继续输入和选择附件、技能、会话引用；Enter 或发送按钮会将这条消息加入队尾。停止按钮保留为独立操作，Shift+Enter 换行，输入法确认候选字时不提交。

队列默认收起，显示待发数量及“当前回复后依次发送”。浮层中可编辑或移除尚未派发的消息；编辑使用独立输入框，保留正在输入的新草稿。当前回复继续执行，但下一条消息会等待编辑完成。编辑窗口有可续期的独占租约，其他窗口不能同时改同一队列。

正常完成一轮，并保存该轮答复后，自动发送下一条。停止、终止错误或派发失败会暂停队列并保留其余消息。用户点击“继续发送”后恢复，正在结束或保存的失败任务必须先释放发送锁。应用重启后所有保留的队列均恢复为暂停状态，不自动执行。切换会话、打开设置或卸载 ChatView 不会丢失已入队消息。

队列每会话最多 50 条。写入成功才清空相应草稿，入队失败保留内容。切换会话时异步完成的入队只清理原会话的草稿、附件和引用，不覆盖新会话。

WebUI、团队和工作流会话暂不显示排队入口；保留其原有发送路径。WebUI 发送也受到主进程的会话锁保护。原有定时发送遇到运行任务或普通队列时等待，未被主进程接受的发送不会被误报为成功或删除。

## 数据与执行

- `conversation_message_queue` 保存按序排列的消息、附件、技能快照、引用会话、模型配置、权限模式和稳定的用户/助手消息 ID。
- `conversation_queue_state` 保存暂停原因和派发错误。队列属于会话，删除会话时按外键级联删除。
- `conversation_queue_receipts` 保留入队凭据及原始载荷摘要；IPC 响应丢失后重试不会重复创建已经接受、移除或执行的消息。
- 入队时冻结输入框显示的可用模型/思考强度等配置默认值以及显式覆盖值，避免后续更改影响已排队消息。队列不保存可执行文件、环境变量或凭据。
- 会话引用在实际派发时通过现有受权限检查的分享接口生成快照，并绑定到稳定用户消息 ID。与普通发送使用相同的上下文注入流程。
- 附件的数据库引用计数同时覆盖正式消息和队列；清空输入框、切换页面和临时文件清理不会删除仍被队列引用的托管附件。

手动发送、定时发送和队列派发共用主进程的会话锁，跨窗口也不能并发启动同一个会话。锁在消息持久化和异步准备前获取。派发中的条目不能编辑或移除。准备失败时释放锁，仍未接受的队首保留供恢复；重试复用消息 ID，不重复插入聊天历史。

主进程接受 CLI 启动后，将该条消息从队列移入正式消息流程。运行失败时，其错误保留在正式答复中，其余条目暂停。运行终止事件先进入“等待保存答复”阶段，`cli:updateMessage` 持久化终态后才释放锁；这样后续消息可读取完整上下文，原始 stdout 经渲染器解析出的错误也会暂停队列。旧任务事件不能释放或修改新任务。

发送准备和编辑租约每 15 秒续期，45 秒未续期可恢复。发送窗口消失或答复未能保存时，不会继续无人值守执行；队列暂停，遗留的运行占位消息恢复为失败状态。稳定会话 ID、任务 ID 和消息 ID 共同避免跨会话串发和重复执行。
