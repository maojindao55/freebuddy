# 每轮文件版本与差异方案

日期：2026-10-13。状态：第一阶段已实现，默认关闭；真实 Qoder / Qwen3.8-Flash 写入及历史读取验收通过。

## 1. 产品决定

采用“FreeBuddy 保存可靠的轮次基准和结束版本，点击时统一计算差异”的路线。现有 ACP 操作记录保留，作为路径发现、执行证据和历史回退来源。

一次对话轮次的差异由已冻结的文件版本决定。更换 Agent 不改变文件版本比较算法。完整 Markdown 预览是版本内容允许时提供的阅读能力，与是否能展示局部操作记录分开。

首期做本地 ACP 会话的只读查看试点，覆盖 Git 和非 Git 工作区；沿用现在的聊天卡片、文件选择器、侧栏与全宽阅读。不增加接受、拒绝或回滚文件操作。

### 必须成立的约束

- 轮次身份使用运行所在主机、owner、conversationId、taskId 与实际工作区根目录。ACP 的 sessionId 可能复用，不能单独标识轮次。
- 基准内容必须在 Agent 开始本轮写入之前保存。收到一个文件变更通知后再读取磁盘，不能证明读到的是修改前内容。
- 结束版本在轮次结束时冻结。查看历史时读取已保存版本，不能读取今天的文件作为历史“修改后”。
- 未采集、被排除、采集失败与文件不存在是不同状态；不能把前三者当作空文件。
- 没有证据时保留未知状态。既不伪造完整差异，也不把缺失记录视为零变化。
- 文件内容采集失败不改变 Agent 的执行结果；差异能力降级并保留原因。

## 2. 两条采集路径

### A. 工作区轮次基准：首期的基础路径

在真正发送 `session/prompt` 前，为实际工作区建立候选文件清单并保存符合预算的文本内容。先把基准清单及版本引用持久化，再让 Agent 执行。

Git 工作区通过 `git ls-files` 的 tracked 和 non-ignored untracked 文件建立候选集，不使用 HEAD 作为本轮基准，也不修改 Git index、分支或提交。这样已有的未提交修改也成为正确的起点。

非 Git 工作区使用受限扫描。遵循项目忽略规则，排除依赖目录和版本控制元数据。Git 与非 Git 都记录“存在但未捕获”的文件状态。清单只有在对应范围枚举完整时，才能证明某个新路径在起点不存在。

轮次结束后重新检查候选集和新增路径，保存结束版本，比较存在性和内容摘要。该路径能覆盖在已采集范围内通过 shell、Agent 自带 Edit 或生成器写入的文件，不要求它们主动调用 ACP 文件接口。

文件系统监听仅提供变化线索、使缓存失效，不能作为修改前正文的来源，也不能代替结束检查。初版不依靠 mtime/size 相等断言内容相等；增量优化必须有可验证的内容摘要和失效机制。

### B. ACP 文件接口：后续增加的受控写入路径

当前 FreeBuddy 没有实现 `fs/read_text_file` 和 `fs/write_text_file`。实现后再声明能力：

1. 复用会话归属、实际工作区根目录及 `workspaceAccess` 权限校验。
2. 写入前保存当前版本作为操作证据；已有轮次基准不得被后续写入覆盖。
3. 按当前权限完成写入，再登记写入结果。文件采集失败时标记缺失，不声称存在可靠基准。
4. 结束时仍冻结最终文件版本；某次写入的内容不能直接替代整轮结束内容。

仅在第一次发现路径时读到的原文，可能已经包含更早的 shell 修改。除非起点清单或受控写入范围能够证明它就是轮次原文，否则它只作为单次操作基准，不能升级为整轮基准。

不要求所有 Agent 使用这条接口，也不为了获得补丁而默认声明 JetBrains AIR 客户端身份。Agent 原生轮次补丁、普通 ACP 补丁和片段均经过输入归一化，进入操作记录回退通道。

## 3. 生命周期与版本保存

流程：`准备基准 → 执行 → 冻结结束版本 → 发布轻量索引 → 点击计算正文差异`。

| 阶段 | 行为 |
|---|---|
| 准备 | 会话保持 starting；用有限预算完成基准采集并持久化。失败或超限仍允许任务运行，记录实际覆盖范围。 |
| 执行 | 采集受控写入证据、文件路径与执行状态。原始 ACP 记录照常保存。流消息不携带快照正文。 |
| 结束 | 正常结束在 prompt response 后冻结；手动停止在取消确认或终止完成后冻结；失败同样保留已发生的文件变化。 |
| 后处理 | 若冻结未完成，卡片显示“正在整理本轮变化”。完成后发布稳定文件列表。 |
| 查看 | 优先读取已冻结的版本对。无版本对时采用有明确范围说明的记录汇总。切换文件继续忽略过期响应。 |

持续运行的后台命令可能在轮次结束后继续写文件。本轮只记录冻结时点的版本，不再改写历史结果；无法排除活跃写入时标记范围不确定。不得无限等待所有后台进程退出。

运行所在目录必须采用实际 worktree 路径；多工作区按明确的 workspaceRoots 采集。远程 Agent 需要在其运行主机实现采集；首期远程会话继续展示操作记录。

### 数据结构

增加独立的版本存储，不覆盖 `file_edit_blobs`：

- `turn_file_capture_runs`：owner、host、conversation、task、roots、状态、起止采集时间、覆盖范围、失败原因、并发范围。
- `turn_file_versions`：规范路径、before/after 时点、存在性、正文引用、摘要、字节数、编码及采集来源。
- `file_version_blobs`：不可变原始字节正文，按 owner 和内容摘要去重；引用按会话归属校验。

协议模型应显式表达 `absent / captured / unavailable`，以及 `snapshot-pair / patch / fragments / missing` 等来源，而不只依赖一个 `partial` 布尔值。读取接口继续分页和分块，复用现有会话归属校验。

文件正文保留 CRLF、末尾换行、空文件和 UTF-8 BOM 的差别。路径保留原始显示形式，比较身份时规范 Windows 大小写和路径分隔符；真实路径必须落在授权根目录中。

采集先检查并发读取一致性：读前后文件状态变化时重试，仍变化则记为 unavailable。跨文件扫描不是原子快照，记录采集区间；Agent 本轮写入在准备完成后才开始。

结束后只保留产生净变化或确有回退需求的正文引用，释放本轮未使用的临时基准。共享正文按引用清理。删除会话沿用级联清理和独立转接快照原则。

## 4. 范围与归因

保存文件前后版本，可以可靠说明两个时点之间的文件变化，但不会自动证明每一行都由本 Agent 写入。

首期：

- 检测 FreeBuddy 内重叠工作区的并行写入轮次，标记“可能包含其他任务的修改”；不悄悄改变现有任务调度。
- 独立 worktree 的会话按其真实目录分别采集。
- 记录捕获到的外部写入线索；用户或外部进程的写入归属无法完全判断，文案使用“本轮文件变化”。
- 真正要求独占 Agent 归因时，后续采用独立 worktree 或受控写入隔离，不能仅靠摘要和文件监听宣称已隔离。

对已捕获的文件比较真实前后版本，不依靠工具成功文本判断文件是否变化。失败任务也可能已经产生写入；无快照的记录回退则继续只纳入确认执行成功的修改。

## 5. 计算、预算与回退

按文件比较存在性与摘要，在索引发布前处理：

- before 存在、after 存在且字节相同：无净变化，卡片与文件选择器都不列出。
- before 不存在、after 存在：新增；新建空文件也保留。
- before 存在、after 不存在：删除。
- 新建后删除且可证明起点/终点都不存在：无净变化。
- 重命名首期可以稳定显示删除与新增；仅在来源证据明确时合并显示重命名，不能凭相同摘要任意配对。
- 正文未知、二进制、文件过大：保留条目和明确状态，不能隐藏或填充为 `+0 / −0`。

摘要比较和索引发布不计算逐行 diff。正文读取、逐行算法、Markdown 渲染仍在点击文件后进行，复用现有有界内存缓存。缓存键包含冻结的版本引用、来源状态和算法版本。

初始试点预算：单文件正文上限 4 MiB、每轮起点正文合计 64 MiB、最多 50,000 个清单条目，准备及结束检查分别设 2 秒软预算。以上是待测默认值，不是已验证的性能结果；超限文件保留明确状态。Agent 开始后不能继续补采原文并将其冒充起点版本。

保存预算、传输预算与 diff 计算预算分别限制。继续沿用现有 64 KiB 分块、8 MiB 预览预算和 diff 算法规模保护。存下正文不代表界面必须内联渲染大文件。

回退次序：

1. 可靠 before/after 版本对：本轮文件差异。
2. 已保存且可校验的补丁或完整版本记录：已记录修改的汇总，保留其覆盖边界。
3. 无法定位的替换片段：局部操作记录，行号明确为片段内行号。
4. 内容缺失：保留文件信息及原因，提供现有读取重试。

历史轮次没有新基准时，继续使用原始记录。已有 Claude、CodeBuddy、AGY 的恢复与兼容先保留在记录通道，不再把这些历史格式容错当作新快照路径的必要条件。旧历史不能用当前工作区补造。

## 6. UI / UX 决定

需要行为和状态调整，沿用现有视觉体系。依据当前分支的实际组件验证页及用户提供的 Qoder 截图，完整检查见 [截图报告](../../../artifacts/product-design/turn-file-diff-baseline/audit.md)。

### 聊天卡片

- 标题使用“本轮文件变化”；列表只在结果冻结后稳定展示。
- 本轮启动和运行期间隐藏文件变化卡片及提示条，结束后才展示本轮文件变化。
- 冻结过程中显示“正在整理本轮变化”，与 Agent 是否仍在生成区分。
- 发布索引时排除已确定无净变化的文件，消除当前“点开后条目消失、数量变化”的行为。
- 未计算增删统计时显示“查看变化”；计算成功后回填准确行数。未计算不显示 0，也不展示虚假的全卡片总行数。
- 全部已确认无净变化时用紧凑状态“本轮没有留下文件变化”。覆盖不完整时不能使用这一结论，改为“部分文件仅有操作记录”。

### 文件阅读区

沿用文件选择器、源码差异、Markdown 预览、全宽/Esc、自动换行和文件间快捷键。

| 数据状态 | 显示与交互 |
|---|---|
| 完整版本对 | 显示“本轮差异”，真实文件行号；Markdown 可切换“本轮修改前 / 本轮修改后”。 |
| 补丁或片段记录 | 显示“操作记录”或“仅局部记录”；统计标明已记录范围。用一条可见说明解释行号和预览边界。 |
| 缺失、超限或二进制 | 明确显示“无法查看完整差异”及具体原因；可读取失败则显示重试，不提供会误导的统计。 |
| 并行范围不确定 | 保留可查看的两个时点版本，并提示“可能包含其他任务的修改”，不能冒充独占 Agent 归因。 |

用户提供的 Qoder 界面目前有两个重复的提示。合并为一个状态说明。Markdown 预览只有在实际保存的版本允许时可用；不可用原因保持可见，不能只放在悬停 tooltip。

“打开文件 / DocStudio”明确为“打开当前文件”，避免把磁盘上的当前版本误认为冻结的历史版本；已删除的文件不提供该操作。

状态使用文字及图标，不只依靠红绿颜色。异步状态通过 aria-live=polite 宣告；保持当前文件和键盘焦点，列表与文件选择器共享同一份稳定索引。试点验证窄侧栏、全宽、Esc 与键盘切换；截图检查不等于完整无障碍验证。

## 7. 分阶段实现

### 第一步：最小闭环

在开发开关下接入本地轮次基准和结束版本，复用现有 `readMessageFileEdit`、卡片与阅读器。暂不新增 ACP 写接口和大范围设置 UI。

用真实 Qoder 场景验证：已有 test.md、同轮三次不相邻修改、Agent 直接写磁盘、结束后显示第 3/5/7 行的完整净差异与 Markdown 前后预览；再验证下一轮和重启后的历史版本不被当前文件污染。

本阶段就处理稳定索引、未采集状态和并行范围提示，不能先做一个始终声称“完整”的演示。

### 第二步：受控文件写入

实现 ACP 文件读写方法，复用统一快照服务与现有权限检查。验证声明该能力与未使用该能力的 Agent 都可继续工作。归一化层只提取有证据的路径、操作与正文，不扩散 Agent 名称判断。

### 第三步：扩大覆盖与性能

验证 Codex、Claude、CodeBuddy、AGY、Pi 等已有集成；再扩展远程主机和大型工程。根据实测调整 CAS、扫描和清理预算。缺乏真实协议证据的 Agent 不标记为已验证。

## 8. 验收标准

| 场景 | 必须验证的结果 |
|---|---|
| A → B → C；A → B → A | 分别得到 A → C 和无净变化，列表在发布后不跳动。 |
| 不相邻三处替换 | 完整版本对显示真实文件行号和完整 Markdown；不依赖成功响应正文格式。 |
| 新建空文件、删除、新建后删除、重建 | 存在性正确，空文件和字节相同的不同存在状态不被误隐藏。 |
| Dirty Git、untracked、非 Git、真实 worktree | 使用轮次起点实际内容，根目录及候选集正确。 |
| shell 或生成器直接写文件 | 在已采集范围内仍能获得版本对；未采集路径明确降级。 |
| Failed、stopped、cancel timeout、后台写入 | 已发生变化保留，结束时点和不确定性明确。 |
| 同目录并行任务、外部编辑 | 不错误宣称全部变化由当前 Agent 产生。 |
| 大文件、二进制、权限错误、预算耗尽、崩溃恢复 | 有界资源、任务可继续、缺失不变成零变化。未封存轮次不能以重启时磁盘内容补造终点。 |
| CRLF、EOF、BOM、Windows 路径、路径越界 | 字节与路径身份正确，读写范围仍受现有权限约束。 |
| 旧会话、会话删除、转接与分享 | 原记录兼容，所属校验、引用清理和独立历史快照成立。 |
| UI 异步读取 | 正文仅点击时传输；列表与选择器一致；状态说明、重试和焦点稳定。 |

运行相关单元/数据库测试、typecheck、Electron 构建，随后在真实 Agent 会话中验证最小闭环。第一阶段的实现与验证记录见下一节。

## 9. 第一阶段实现与试用

已接入本地 ACP 的 prompt 前采集与结束封存、不可变版本存储、按需读取、稳定索引和 UI 状态。旧 Agent 兼容与历史恢复保留作操作记录回退，暂不增加 ACP 文件接口、远程隔离会话采集或文件回滚。

文件枚举、读取、UTF-8 校验与哈希计算在独立 Electron utility process 中执行。主进程保留所属校验、并发范围标记和 SQLite 入库；每批最多 32 个版本，正文目标上限 1 MiB，单个较大文件单独传输并受 4 MiB 文件预算限制。主进程在批次之间回到事件循环，并在入库完成后确认，采集进程才发送下一批；结束时相同版本只传元数据。采集进程复用、单进程排队，空闲 30 秒释放，应用退出时终止；异常退出、超时或入库失败降级为不完整，保留已封存版本对，释放没有结束版本的临时基准。准备/结束仍分别等待可靠基准和结束版本保存，后台进程不会消除这两个时点的等待。

本地 ACP 会话默认启用采集，开发环境与正式包使用相同逻辑，无须环境开关。在本仓库中直接试用：

```powershell
npm run dev
```

没有采集快照的历史轮次仍使用已保存操作记录，不能补造文件起点。

验证：相关 Node 测试 231 项通过、1 项符号链接测试跳过；文件变化数据库测试 50 项通过、1 项 Windows 文件符号链接测试跳过；真实 Qoder opt-in 测试 1 项通过。Windows 目录 junction 越界验证已通过。typecheck、Electron 构建及真实 React 组件浏览器操作已验证；最终运行结果记录在 [体验报告](../../../artifacts/product-design/turn-file-diff-baseline/audit.md)。

真实 Qoder opt-in 测试使用用户指定的 Qwen3.8-Flash。该安装实例的 ACP 目录将它声明为 `qfmodel`，名称为 `Qwen3.8-Flash (default)`，描述为 `0.00x Credit`。测试通过实际 ACP 运行时代码发送初始化、模型选择和 prompt，在发送前断言基线已持久化；三次独立编辑得到完整第 3/5/7 行差异。随后改变当前磁盘文件，将快照数据库保存并重新打开，仍读取到正确的历史原文和结束版本。验证结果保存为 [qoder-live-result.json](../../../artifacts/product-design/turn-file-diff-baseline/qoder-live-result.json)。

测试文件为 `tests/turn-file-snapshots-qoder-live.test.mjs`，默认不启动 Agent，需显式提供以下运行参数：

- `FREEBUDDY_QODER_ENTRY`：已安装的 Qoder CLI JavaScript 入口。
- `FREEBUDDY_QODER_NODE`：Node 可执行文件。
- `FREEBUDDY_QODER_MODEL`：ACP 目录中对应的模型 ID，不按显示名称猜测。
- 可选 `FREEBUDDY_QODER_EVIDENCE`：写入合成测试文档与结果的证据路径。
